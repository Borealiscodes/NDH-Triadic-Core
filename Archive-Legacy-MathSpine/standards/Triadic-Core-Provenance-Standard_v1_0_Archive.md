# **NDH‑Triadic‑Core Provenance Standard v1.0**  
**Formal Provenance Rules for Mathematical Artifacts**

---

## **1. Scope of the Triadic‑Core**

The NDH‑Triadic‑Core contains:

- mathematical operators  
- geometric substrates  
- stability envelopes  
- tensor rules  
- invariants  
- continuity bounds  

It must remain:

- mathematically closed  
- citation‑free  
- interpretation‑free  
- literature‑free  
- narrative‑free  

The Core is a **pure mathematical manifold**, not a semantic or interpretive layer.

---

## **2. Provenance Footer Requirements**

Every Triadic‑Core artifact must include a provenance footer containing:

### **2.1. Artifact Identity**
A short statement describing:

- what the artifact defines  
- what mathematical role it plays  
- which operators or geometric structures it relates to  

### **2.2. Citation‑Free Declaration (Mandatory)**  
Every provenance footer must include the following exact text:

```markdown
Note: The NDH‑Triadic‑Core contains no internal citations. All interpretive,
literature, and provenance references are handled by the Reflection Layer in
Zen‑AI‑Design‑Architecture, which maintains the citation ontology and merged
citation blocks.
```

This ensures:

- mathematical purity  
- architectural separation  
- correct provenance routing  
- NDH v1.1 compliance  

### **2.3. Maintainer Line**
Every artifact must end with:

```markdown
Maintainer: Borealis S. Hedling • Dublin, Ireland • 2026
```

This establishes authorship and version lineage.

---

## **3. What Must NOT Appear in Triadic‑Core Provenance**

The following must **never** appear in Triadic‑Core provenance footers:

- citations  
- literature references  
- case studies  
- expressive geometry references  
- file paths to Reflection Layer artifacts  
- links to citation blocks (including CitationBlock‑v2.0)  
- interpretive commentary  
- narrative context  
- ethical framing  
- human‑rights framing  
- Zen metaphors  
- constellation metaphors  

These belong exclusively to the **Reflection Layer**.

---

## **4. Allowed Cross‑Layer References**

Triadic‑Core provenance may reference:

- the Reflection Layer **as a subsystem**  
- the citation ontology **as a subsystem**  
- the merged citation blocks **as a subsystem**

But **never** specific files or paths.

Correct:

> “Handled by the Reflection Layer in Zen‑AI‑Design‑Architecture.”

Incorrect:

> “See CitationBlock‑v2.0.md in Constellation‑Reflections.”

---

## **5. Operator Provenance Structure**

All operator files (Crane, Scarf, Manifold) must follow this structure:

1. **Operator Purpose**  
2. **Formal Definition**  
3. **Mathematical Constraints**  
4. **Operator Relationships**  
5. **Provenance Footer (with citation‑free declaration)**  

No additional sections are permitted.

---

## **6. Stability Geometry Provenance Structure**

Stability Manifold artifacts must follow:

1. **Stability Envelope Definition**  
2. **Safe Region Definition**  
3. **Basin Definition**  
4. **Drift Bounds**  
5. **Operator Integration**  
6. **Provenance Footer (with citation‑free declaration)**  

---

## **7. Versioning Rules**

Triadic‑Core artifacts must use:

- **v1.0** for first formal mathematical definitions  
- **v1.1** for operator refinements  
- **v2.0** only for major mathematical restructuring  

Version numbers must never be reused.

---

## **8. File Naming Rules**

Files must follow:

```
<Name>-v<Major>.<Minor>.md
```

Examples:

- Crane-Operator-v1.1.md  
- Scarf-Operator-v1.0.md  
- Manifold-Operator-v1.0.md  
- NDH-Stability-Manifold-v1.0.md  

No expressive names.  
No narrative names.  
No case‑study names.

---

## **9. Architectural Separation Rule**

The Triadic‑Core must never depend on:

- Reflection Layer file paths  
- Expressive Geometry artifacts  
- Citation blocks  
- Case studies  
- Emergent examples  

The dependency direction is:

**Triadic‑Core → Reflection Layer (semantic)**  
**Reflection Layer → Triadic‑Core (interpretive)**

Never the reverse.

---

## **10. Publication Rule**

Triadic‑Core artifacts must be:

- self‑contained  
- mathematically complete  
- citation‑free  
- Zenodo‑ready  
- provenance‑consistent  

This standard ensures NDH v1.1 mathematical integrity.
